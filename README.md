# loggerlib

Библиотека логирования и две консольные программы, которые её используют.

Библиотека пишет сообщения в лог — в файл, в сокет или сразу в несколько мест — и отбрасывает
всё, что ниже заданного порога важности. Приложение показывает её в работе: читает строки с
клавиатуры и отдаёт их на запись отдельному потоку. Коллектор принимает лог из сокета, печатает
пришедшие записи и считает по ним статистику.

Всё написано на C++17, STL. Собирается через cmake, целевая система — Ubuntu/Debian.

## 2. Сборка и запуск

Требования: cmake 3.16 или новее, компилятор с C++17 (проверяется на gcc 13), pthreads. Сторонних
библиотек нет, doxygen нужен только для цели `docs`.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
```

После сборки в `build/lib` лежат `liblogger.so` и `liblogger.a`, в `build/bin` — `logger_app` и
`logger_collector`. Обе библиотеки собираются из одного списка исходников, `BUILD_SHARED_LIBS`
выбирает, с какой слинкуются программы.

### Цели сборки

| Цель | Назначение |
|---|---|
| `logger_shared`, `logger_static` | два варианта библиотеки, а `Logger::Logger` указывает на выбранный |
| `logger_net` | объектная цель из `common/net`, её код встраивается в те цели, которые работают с сокетами |
| `app_core`, `logger_app` | логика приложения |
| `collector_core`, `logger_collector` | то же самое для коллектора |
| `logger_tests`, `app_tests`, `collector_tests` | CTest заводит отдельную цель на каждый сьют |

### Параметры сборки

| Опция | По умолчанию | Назначение |
|---|---|---|
| `BUILD_SHARED_LIBS` | `OFF` | выбирает, на какую из двух библиотек указывает `Logger::Logger` |
| `LOGGER_BUILD_APP` | `ON` | собирать ли демонстрационное приложение |
| `LOGGER_BUILD_COLLECTOR` | `ON` | собирать ли коллектор статистики |
| `LOGGER_BUILD_TESTS` | `ON` | собирать ли тесты и заводить ли их в CTest |
| `LOGGER_BUILD_DOCS` | `OFF` | добавляет цель `docs` с документацией по публичным заголовкам |
| `LOGGER_ENABLE_WARNINGS` | `ON` | включает `-Wall -Wextra -Wpedantic` |
| `LOGGER_ENABLE_WERROR` | `OFF` | включает `-Werror`, CI (`ON`) |

### Документация

```bash
cmake -S . -B build -DLOGGER_BUILD_DOCS=ON
cmake --build build --target docs      # build/docs/html/index.html
```

Пропущенное описание или забытый `@param` в публичном заголовке роняют цель. Сгенерированное в
репозиторий не попадает. Внутренние заголовки в цель не входят: проверка следит за публичным API.

### Запуск тестов

`ctest` прогоняет по цели на сьют плюс проверку записи через динамическую библиотеку. Бинарник
можно запускать и напрямую:

```bash
./build/bin/logger_tests --list                 # перечислить тесты
./build/bin/logger_tests --suite log_record     # прогнать один сьют
./build/bin/app_tests --filter level            # отобрать по подстроке имени
./build/bin/collector_tests --suite statistics  # сьюты коллектора
```

### Запуск приложения

```
logger_app [--] <logfile> [level]
logger_app [--file <path>] [--socket <host:port> [--proto tcp|udp]] [--level <name>]
logger_app --help
```

`<logfile>` и `--file` задают файлы, `--socket` — адреса. Обе опции можно повторять и смешивать:
запись уйдёт во всё перечисленное. `--proto` задаёт транспорт для того
`--socket`, за которым стоит, по умолчанию TCP. `--level` — начальный порог, одно из
`DEBUG, INFO, WARN, ERROR, FATAL`, регистр не важен, по умолчанию `INFO`. После `--` опции
заканчиваются, так что имя файла может начинаться с дефиса. Адрес IPv6 пишется в скобках:
`--socket [::1]:5555`.

Аргумент без дефиса считается именем файла, пока не названо ни одной цели, а дальше читается как
уровень. Поэтому работают обе формы: `logger_app app.log WARN` и
`logger_app --socket 127.0.0.1:5555 WARN`.

```bash
logger_app app.log --file audit.log --socket 127.0.0.1:5555 --socket [::1]:6666 --proto udp WARN
```

| Ввод | Действие |
|---|---|
| `disk almost full` | сообщение с текущим уровнем |
| `WARN disk almost full` | первое слово — имя уровня, остальное — текст сообщения |
| `/level DEBUG` | сменить уровень |
| `/help` | показать список команд |
| `/quit` | закончить работу, то же делает `Ctrl-D` |
| `//quit` | записать сообщение с текстом `/quit` |
| пустая строка | ничего |

Приглашение `> ` печатается, только если ввод идёт с терминала.

```console
$ printf 'hello\nWARN disk almost full\nDEBUG hidden\n/level DEBUG\nDEBUG now visible\n' \
    | logger_app demo.log INFO
level: DEBUG
processed 3 message(s), 0 failed

$ cat demo.log
2026-08-19 19:27:45.960Z [INFO] hello
2026-08-19 19:27:45.961Z [WARN] disk almost full
2026-08-19 19:27:45.961Z [DEBUG] now visible
```

Строки `DEBUG hidden` в логе нет, потому что в тот момент порог был `INFO`.

### Коды возврата

| Код | Приложение | Коллектор |
|---|---|---|
| 0 | работа закончена, всё принятое записано | остановлен сигналом |
| 1 | ошибка в аргументах командной строки | то же |
| 2 | лог не удалось открыть | сокет не удалось открыть |
| 3 | хотя бы одна запись не удалась | приём оборвался |
| 4 | внутренняя ошибка, до `main` дошло исключение | то же |

При отказе записи приложение продолжает принимать ввод, печатает причину при каждой её смене и
называет последнюю в итоговой строке:

```console
$ printf 'one\ntwo\n' | logger_app /dev/full DEBUG
log write failed: No space left on device
processed 0 message(s), 2 failed: No space left on device
$ echo $?
3
```

## 3. Библиотека

```cpp
#include <logger/LoggerFactory.hpp>

std::error_code ec;
auto logger = Logger::createLogger(Logger::SFileTarget{"app.log"}, Logger::ELogLevel::Info, ec);
if (!logger) return report(ec);            // файл не открылся

(void)logger->log(Logger::ELogLevel::Warn, "disk almost full");
logger->setLevel(Logger::ELogLevel::Debug);
```

Наружу выставлен один интерфейс `ILogger` с тремя виртуальными операциями: `log`, `setLevel` и
`level`.

### Устройство

```
   createLogger(цели, порог)
            △
            │
     SinkLogger                    форматирует запись, хранит порог, держит мьютекс
            ◆  writeLine(строка)
            │
          ISink ◁┬── FileSink      ofstream, flush после каждой записи
                 ├── TcpSink       переподключается сам, с растущей паузой
                 ├── UdpSink       одна датаграмма на запись
                 └── MultiSink     раздаёт строку остальным
```

Порог и мьютекс живут только в `SinkLogger`, поэтому реализациям `ISink` не нужно ни
синхронизироваться, ни повторно проверять уровень. Каждая получает готовую строку и доставляет её
по назначению.

### Цели записи

`createLogger` принимает либо одну цель, либо список:

```cpp
const auto logger = Logger::createLogger(
    {Logger::SFileTarget{"app.log"},
     Logger::SSocketTarget{"127.0.0.1", 5555, Logger::ESocketProtocol::Tcp}},
    Logger::ELogLevel::Info, ec
);
```

Запись при этом **форматируется один раз** и уходит каждой цели, поэтому таймстамп у всех
одинаковый. Если хотя бы одну цель не удалось открыть, фабрика возвращает
`nullptr` и записывает причину в `ec`. Если при записи отказала хотя бы одна цель, `log` возвращает
`false`, а `ec` называет первый отказ, но остальные цели запись всё равно получают.

**Файл** создаётся, если его нет, а после каждой записи вызывается `flush`.

**TCP.** Соединение открывается сразу при создании логера, и если открыть его не удалось, фабрика
возвращает `nullptr`. Оборванную связь логер восстанавливает сам: следующая запись пробует
подключиться заново, пауза между попытками растёт с 50 мс вдвое до секунды и обнуляется после
удачной, адрес перезапрашивается каждую пятую неудачу подряд.

**UDP.** Библиотека отправляет по одной датаграмме на запись. Слишком длинную она не режет, а
отвергает: `log` возвращает `false` с кодом `std::errc::message_size`.

### Уровни

В `Logger::ELogLevel` пять уровней — `Debug`, `Info`, `Warn`, `Error`, `Fatal` — и служебный
`Count`. Запись попадает в лог, если её уровень **не ниже** текущего порога. `level2string` и
`string2level` переводят уровень в строку и обратно.

### Формат записи

Одна запись — одна строка. По этому формату пишет `formatRecord` и читает `parseRecord`, он же
служит договором между библиотекой и коллектором.

```
2026-08-19 19:27:45.960Z [WARN] disk almost full
└────── 24 символа ────┘ └уров┘ └─ сообщение ──┘
```

Таймстамп занимает ровно 24 символа в виде `YYYY-MM-DD hh:mm:ss.mmmZ` и хранит время получения
сообщения **всегда в UTC**. Уровень записывается в квадратных скобках, отделённый пробелами. Дальше
идёт текст сообщения, в котором управляющие символы экранированы.

Если время не удалось разложить в календарную дату, вместо таймстампа пишется
`0000-00-00 00:00:00.000Z`, и такую строку `parseRecord` не принимает уже по устройству разбора.

### Экранирование

| Символ | В логе |
|---|---|
| `\` | `\\` |
| перевод строки, возврат каретки, табуляция | `\n`, `\r`, `\t` |
| остальные символы с кодом ниже `0x20`, а также `0x7F` | `\xNN`, две шестнадцатеричные цифры |
| всё прочее, включая байты выше `0x7F` | как есть, UTF-8 не портится |

### Границы разбора

`parseRecord` принимает только то, что библиотека способна написать:

- дата должна существовать, так что `2026-02-31`, `2026-13-01` и `25:99:99` отвергаются;
- время не раньше эпохи;
- время не позже последнего момента, который умещается в `std::chrono::system_clock`. Эта граница
  зависит от реализации: у libstdc++ тик наносекундный и потолок приходится на 2262 год, у libc++
  тик микросекундный и максимум недостижим.

### Ошибки

Исключения для бизнес-логики не используются, вместо них три способа:

| Ситуация | Форма | Где |
|---|---|---|
| ошибка пересекает границу API и на неё можно среагировать | `std::error_code&` | `ILogger::log`, `createLogger`, `IReceiver::receive` |
| результат либо есть, либо его нет | `std::optional` | `string2level`, `parseRecord`, `splitHostPort` |
| несколько исходов и пользовательский ввод | `std::variant` | `parseUserInput`, `parseOptions` |

`std::error_code` очищается в начале операции и остаётся непустым тогда и только тогда, когда
операция вернула `false` или `nullptr`. Сообщение, отброшенное по уровню, — это успех с чистым
кодом.

### Потокобезопасность

`log`, `setLevel`, `level` и `isEnabled` можно звать из любого числа потоков. Порог хранится
атомарно, запись защищена мьютексом. Тест пишет 1000 записей из четырёх потоков и получает 1000
целых строк.

## 4. Приложение

Потоков два, связывает их очередь событий:

```
        главный поток                                    рабочий поток
 ┌───────────────────────────┐                    ┌───────────────────────────┐
 │ getline из stdin          │     EventQueue     │ pop, ждёт событие         │
 │ parseUserInput            │  ┌──────────────┐  │                           │
 │   сообщение ──────────────┼─►│ Write        │─►│ ILogger::log ────► лог    │
 │   /level ─────────────────┼─►│ SetLevel     │─►│ ILogger::setLevel         │
 │   /help, /quit, ошибки    │  └──────────────┘  │ счётчики, причина отказа  │
 └───────────────────────────┘                    └───────────────────────────┘
              ▲                                                  │
              └────────── processed(), failed(), lastError() ────┘
```

| Класс | Ответственность |
|---|---|
| `Options` | разбирает аргументы командной строки и печатает помощь |
| `InputParser` | разбирает одну строку ввода: сообщение, команда, ошибка или пустая строка |
| `EventQueue` | передаёт события между потоками и умеет ждать, не крутя процессор |
| `LogWorker` | единственный, кто пишет: владеет потоком, ведёт счётчики и помнит причину отказа |
| `ConsoleApp` | читает ввод, печатает диагностику, подводит итог и выбирает код возврата |

Разбор идёт в главном потоке: ответ вроде `unknown level: NOPE` должен появляться сразу. В очередь
попадает уже разобранное событие.

### Инвариант завершения

1. `EventQueue::close()` закрывает очередь для новых событий, но принятое не выбрасывает: `pop`
   выходит по пустой очереди, а не по факту закрытия;
2. `LogWorker::stop()` закрывает очередь и дожидается конца потока;
3. Деструктор `LogWorker` сам вызывает `stop()`.

### Прочие решения

- **Смена уровня происходит через очередь**;
- **Очередь не ограничена.**;
- **`processed()` считает записанное, а не принятое**, чтобы не считать отброшенные по порогу;
- **Исключения ловятся на двух границах** — в теле рабочего потока и в `main`. Исключение,
  покинувшее функцию потока, означает `std::terminate`. Пойманное исключение считается неудачной
  записью.

## 5. Коллектор

```
logger_collector [--] <host:port> [N] [T]
logger_collector --listen <host:port> [--proto tcp|udp] [--count N] [--timeout T]
logger_collector --help
```

`<host:port>` задаёт локальный адрес и порт, на которых коллектор ждёт соединений. Запись `:5555`
означает любой адрес машины, то есть подключиться смогут и с других узлов сети. `127.0.0.1:5555`
ограничивает приём адресом обратной связи, и тогда сообщения принимаются только от процессов на той
же машине. Адрес IPv6 записывается в квадратных скобках: `[::1]:5555`.

`N` (по умолчанию 100) задаёт, через сколько принятых сообщений печатать статистику, `T` (по
умолчанию 10) — через сколько секунд печатать её ещё и по времени, но **только если с прошлой выдачи
что-то пришло**. Позиционная и именованная формы равнозначны.

```console
$ logger_collector 127.0.0.1:5555 3 1 &
listening on 127.0.0.1:5555 tcp, reporting every 3 messages or 1 s

$ printf 'hello\nWARN disk almost full\nERROR boom\n' | logger_app --socket 127.0.0.1:5555
2026-08-20 22:37:01.184Z [INFO] hello
2026-08-20 22:37:01.184Z [WARN] disk almost full
2026-08-20 22:37:01.184Z [ERROR] boom
--- statistics (after 3 messages) ---
total 3  last hour 3  malformed 0
by level  DEBUG 0 INFO 1 WARN 1 ERROR 1 FATAL 0
length    min 4  max 16  average 8.3
```

`SIGINT` (`Ctrl-C`) и `SIGTERM` печатают последнюю статистику и завершают работу.

| Что считается | Как |
|---|---|
| `total` | разобранные записи |
| `malformed` | строки, которые записью не являются, и те, что отброшены по длине. Пустая строка сюда не идёт |
| `last hour` | записи за последний час **по времени приёма**, кольцо из 60 минутных корзин |
| `by level` | по уровню важности из самой записи |
| `min`, `max`, `average` | длины текста **без экранирования** |

Записи печатаются в том виде, в каком пришли. Строку, которую `parseRecord` не
принял, уходит в `stderr`, обрезанная до 80 символов и экранированная.

### Устройство

```
      сокет                   один поток
 ┌──────────────┐   ┌────────────────────────────────────┐
 │ TcpReceiver  │   │ poll до ближайшего срока выдачи    │
 │  accept,     │──►│ parseRecord ┬─► печать записи      │
 │  до 16 связей│   │             └─► Statistics         │
 │ UdpReceiver  │   │ выдача: N сообщений или T секунд   │
 └──────────────┘   └────────────────────────────────────┘
```

| Класс | Ответственность |
|---|---|
| `Options` | разбирает аргументы и печатает помощь |
| `Listener` | привязывает сокет: `AI_PASSIVE`, `SO_REUSEADDR`, `bind`, `listen` |
| `TcpReceiver` | опрашивает слушающий и клиентские сокеты, у каждой связи свой `LineReader` |
| `UdpReceiver` | одна датаграмма — одна запись, между датаграммами ничего не хранит |
| `LineReader` | собирает строки из частичных `recv` и следит за их длиной |
| `Statistics` | считает, но часов внутри не держит, момент времени ей передают |
| `CollectorApp` | ведёт цикл, печатает записи и решает, когда выдавать статистику |

## Разработка

В CI (GitHub Actions) на каждый push проверяются: сборка и тесты в четырёх сочетаниях
